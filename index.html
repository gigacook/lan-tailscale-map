Why the HP can receive but can't send in LocalSend

Both laptops are on the same home Wi‑Fi (192.168.1.0/24), but Tailscale on the HP takes over traffic meant for that Wi‑Fi range and sends it into the tunnel instead.

Now broken

The HP accepts a Tailscale subnet route for 192.168.1.0/24, probably advertised by the NAS. So "send to the Mac at 192.168.1.111" goes into the tunnel and never reaches the Mac.

After fix working

With "Use Tailscale subnets" off, Wi‑Fi addresses stay on Wi‑Fi. Tailscale still works for its own 100.x addresses and MagicDNS names.

Fix on the HP (2 minutes)

  1. Check where the traffic goes. Open PowerShell and run: 
    Find-NetRoute -RemoteIPAddress 192.168.1.111 | Select InterfaceAlias
Test-NetConnection 192.168.1.111 -Port 53317
    If it says Tailscale, this map is the problem. If it says Wi-Fi, skip to step 4.
  2. Turn off the subnet route: click the Tailscale icon in the system tray → Settings → uncheck Use Tailscale subnets.
  3. If he needs the NAS subnet over Tailscale, change the NAS so it doesn't advertise 192.168.1.0/24 (the same range as the home Wi‑Fi). Give the NAS's own LAN a different range (e.g. 192.168.50.0/24), or reach the NAS by its Tailscale name or 100.x address instead.
  4. Windows firewall: Settings → Network & internet → Wi‑Fi → his network → Private. Then Windows Security → Firewall → Allow an app → tick LocalSend for Private.
  5. Restart LocalSend on both laptops, then send by IP: Send tab → address icon → 192.168.1.111.
